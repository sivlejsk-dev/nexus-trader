# Nexus Trader — Render Deployment Guide

## Architecture on Render

```
GitHub repo
    │
    ├── nexus-backend   (Render Web Service — Docker, FastAPI)
    │       └── nexus-db  (Render Disk — SQLite at /data/nexus_memory.db)
    │
    └── nexus-frontend  (Render Web Service — Docker, Next.js)
```

The frontend proxies all `/api/*` requests to the backend via Next.js rewrites —
no CORS issues, no API URL exposed to the browser. In Render, the proxy uses
the backend service's private `host:port`, injected by the Blueprint.

## Step 2 — Create a Blueprint deployment

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect your GitHub/GitLab account and select the `nexus-trader` repo
3. Render detects `render.yaml` automatically — click **Apply**
4. For every `sync: false` environment variable, Render will prompt you to enter
   the value before deploying. The app can boot without keys by falling back to
   local analysis and delayed Yahoo Finance market data, but fill in the keys
   below for the full Nexus experience:

   | Variable | Where to get it |
   |---|---|
   | `NEXUS_API_KEY` | [platform.openai.com](https://platform.openai.com) or [console.groq.com](https://console.groq.com) |
   | `GROQ_API_KEY` | [console.groq.com](https://console.groq.com) — free tier available |
   | `POLYGON_API_KEY` | [polygon.io](https://polygon.io) — free tier: 5 req/min |
   | `ALPHA_VANTAGE_API_KEY` | [alphavantage.co](https://www.alphavantage.co) — free: 25 req/day |
   | `TRADIER_API_KEY` | [developer.tradier.com](https://developer.tradier.com) — free sandbox |
   | `JWT_SECRET_KEY` | Auto-generated by Render (`generateValue: true`) |

   Optional (improve research quality):

   | Variable | Notes |
   |---|---|
   | `SERPER_API_KEY` | Google search results via [serper.dev](https://serper.dev) |
   | `BRAVE_API_KEY` | [api.search.brave.com](https://api.search.brave.com) |
   | `NEWS_API_KEY` | [newsapi.org](https://newsapi.org) |

5. Click **Deploy** — both services build in parallel. The frontend receives
   `BACKEND_API_HOSTPORT` from the backend service automatically and proxies
   `/api/*` over Render's private network on the first launch.

## Persistent Storage (SQLite)

The backend uses a **Render Disk** (1 GB) mounted at `/data`.
The database file is `/data/nexus_memory.db`.

- The disk persists across deploys and restarts — all conversation memory,
  predictions, learned weights, and optimization history are preserved.
- The disk is **not** shared between service instances. If you ever scale to
  multiple backend instances, migrate to PostgreSQL first (see below).
- To back up the database:

  ```bash
  # Via Render Shell (dashboard → nexus-backend → Shell)
  cp /data/nexus_memory.db /data/nexus_memory.db.bak
  ```

## Environment Variables Reference

All variables are set in `render.yaml`. Secrets (`sync: false`) must be entered
in the Render dashboard and are never stored in the repo.

### Backend

| Variable | Required | Default | Description |
|---|---|---|---|
| `NEXUS_DB_PATH` | yes | `/data/nexus_memory.db` | SQLite file path |
| `ENVIRONMENT` | yes | `production` | Enables production logging |
| `CORS_ORIGINS` | yes | — | JSON array of allowed frontend origins |
| `NEXUS_API_KEY` | yes* | — | OpenAI-compatible LLM key |
| `NEXUS_API_BASE_URL` | no | `https://api.openai.com/v1` | LLM endpoint |
| `NEXUS_MODEL` | no | `gpt-4o` | LLM model name |
| `GROQ_API_KEY` | yes* | — | Groq fallback key |
| `GROQ_MODEL` | no | `llama-3.3-70b-versatile` | Groq model |
| `POLYGON_API_KEY` | recommended | — | Real-time quotes + options chain |
| `ALPHA_VANTAGE_API_KEY` | recommended | — | Historical OHLCV fallback |
| `TRADIER_API_KEY` | recommended | — | Options chain data |
| `TRADIER_BASE_URL` | no | `https://api.tradier.com/v1` | Use sandbox for testing |
| `SERPER_API_KEY` | optional | — | Google search results |
| `BRAVE_API_KEY` | optional | — | Brave search results |

### Frontend

| Variable | Required | Description |
|---|---|---|
| `BACKEND_API_HOSTPORT` | yes | Render-injected private backend `host:port` used by Next.js rewrites |
| `BACKEND_API_URL` | optional | Public or private backend URL override; useful outside Render |
| `NODE_ENV` | yes | Must be `production` |

## Keeping the App Updated

Every `git push origin main` triggers an automatic redeploy of both services.

To deploy manually from the dashboard: **nexus-backend** → **Manual Deploy** → **Deploy latest commit**.

### Zero-downtime deploys

Render performs rolling deploys by default — the old container stays up until
the new one passes its health check (`/health` for the backend, `/` for the
frontend).

---

## Upgrading from Free Tier

The free tier spins down after 15 minutes of inactivity (cold start ~30s).
To keep the app always-on, upgrade the plan in `render.yaml`:

```yaml
plan: starter   # $7/month per service — always-on, no cold starts
```

---

## Migrating to PostgreSQL (optional, for scale)

If you need multiple backend instances or want managed backups, replace SQLite:

1. Add a Render PostgreSQL database to `render.yaml`:

   ```yaml
   databases:
     - name: nexus-postgres
       plan: free
       databaseName: nexus
       user: nexus
   ```

2. Update `DATABASE_URL` in the backend env vars to the Render internal URL.
3. Replace `aiosqlite` with `asyncpg` and update `app/db/database.py`.

For most single-user or small-team deployments, SQLite on a Render Disk is
sufficient and simpler to operate.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Backend returns 502 | Check logs: dashboard → nexus-backend → Logs. Usually a missing env var. |
| Frontend shows "Failed to fetch" | Verify `BACKEND_API_URL` matches the backend's Render URL exactly (no trailing slash). |
| Cold start timeout | Upgrade to `starter` plan or add an uptime monitor (e.g. [UptimeRobot](https://uptimerobot.com)) to ping `/health` every 5 min. |
| SQLite "database is locked" | Ensure `--workers 1` is set in the uvicorn CMD (already set in the Dockerfile). |
| Options chain returns empty | Set `TRADIER_BASE_URL=https://api.tradier.com/v1` (not the sandbox URL) and verify your Tradier key has live data access. |
